# Home 控制页体验 review — 2026-10-23

本轮只做体验检查、代码审查和问题复现，没有修改应用或正式测试源码，没有安装到用户的 iPad。

## 场景、范围与验收方式

场景：iPad 横向挂墙，远看家庭状态，近距离直接开关设备、调节参数、查看摄像头和控制音乐；需要时添加、移除或改变控件大小。

保留已确认的结构：左侧三列正方形基准单元，控件增加后向下滚动；右侧固定宽矩形列，行高与左侧对齐。保留大温控、液态玻璃、图标直接开关／文字打开详情，不重新加入“某某之家”、房间顶栏、首页照片或提醒。

检查覆盖：首屏与溢出、两个横屏方向、中文和大字号、开关／参数调节、长按与编辑、房间筛选、摄像头配置和快照代码、音乐卡、加载／离线／权限边界。用独立模拟器与明确标记的 DEMO／TEST DATA 验证，真实 HomeKit 写入、摄像头视频及快照、AirPlay、真实音乐声音另行验收。

## 结论

现有大框架可以继续保留。优先处理数据范围、可读性、编辑结果反馈及摄像头一致性，再统一编辑与设备选择入口。当前最明显的视觉问题之一是浅背景下信息失去对比度；单纯调整背景色或继续改变卡片排布不能解决它。

### R1 — 高优先级：抽屉里的房间筛选悄悄影响首页

**已复现。** 打开“全部控制”，选择厨房，关闭弹层后，首页客厅温控和卧室风扇也被筛掉：温控／设备位置变成“此房间没有”的空状态。首页没有筛选提示，用户容易以为设备丢失。手动固定的设备卡与默认分类卡又采用不同的数据范围。

原因：`Dashboard.visibleTiles` 共用 `selectedRoom`；抽屉 `roomChoices` 修改这一值，默认分类卡随之过滤，而指定设备卡直接读取 `home.tiles`。冻结版本 `Dashboard.swift:345,578,691,888`。

建议：房间筛选只作用于“全部控制”弹层，首页始终展示用户选定的设备。无需恢复用户已经去掉的房间顶栏。

验收：依次切换厨房／卧室后返回首页，固定设备和默认分类的显示范围均不变；抽屉仍可独立筛选；切换家庭时旧筛选不能污染新家庭。

证据：`probe-shots/review-home-silently-retains-kitchen-filter-from-controls-drawer.png`。

### R2 — 高优先级：浅色照片背景下文字、图标和温度几乎不可见

**已复现并查看原始截图。** 在独立模拟器使用原创近白色渐变作为已保存照片背景，温度、时钟、白色设备图标与标签几乎融入背景，仅黄色灯泡仍明显。这是正常照片背景功能需要覆盖的边界。

原因：仪表盘统一白色前景，卡片采用透明 `.glassEffect(.clear)`，没有相应的前景对比度保护。冻结版本 `Dashboard.swift:176,1162`。

建议：保留系统液态玻璃和用户背景，在控件层提供可靠的对比度，例如适度深色衬底或可读前景方案；统一处理开启、关闭、禁用和离线状态。不要用重新添加“开启／关闭”小字弥补颜色可读性。

验收：近白、近黑、明暗混合照片及音乐封面背景均能辨认设备名、数值、操作图标和状态；既有照片轮播页不被改动。

证据：`home-synthetic-light-wallpaper.png`。照片只注入独立模拟器的保存文件，不涉及用户相册或权限；截图后已移除该合成文件并关闭本轮模拟器。

### R3 — 中优先级：添加成功，却看不到刚添加的控件

**已复现。** 默认布局添加一个时钟，弹层关闭后画面基本不变。新卡片初始位置为 `(12,834,262,262)`，整个视口高度为834点；用户必须自行上滑才看到它。

原因：`addWidget` 仅追加配置并关弹层，滚动容器没有定位新卡片。冻结版本 `Dashboard.swift:606,719`。

建议：添加后自动滚到新卡片并短暂高亮；改变大小时也确保选中项仍可见。保留三列与向下增加行的规则。

验收：首屏已满和长列表末端添加均可立即看见结果；连续添加、移除和重新打开后的持久化仍正确。

证据：`probe-shots/review-just-added-clock-is-outside-viewport-without-reveal.png`、`review-new-clock-exists-after-manually-scrolling.png`。

### R4 — 高优先级：摄像头配置与首页展示不一致

**代码确认，真实摄像头未复测。** 右侧摄像头编辑器提供“第一台可用摄像头”，保存为空 target；点击时确实回退到第一台，但卡片获取快照的 `camera(for:)` 要求明确 target，空 target 返回 nil。因此该配置可以打开摄像头，却无法在首页解析同一台设备并刷新快照。

左侧摄像头控件使用另一套纯图标入口，大尺寸也不会成为右侧那样的快照卡。用户添加了同名功能，获得的能力却取决于所在列；放大后仍只有图标和大量空白。

原因：冻结版本 `Dashboard.swift:705–710,812–814,829–835,850–876,914–917` 与 `CameraConnectionView.swift:74,128` 的来源解析和内容组件不一致。

建议：统一摄像头来源解析与卡片内容，明确“指定摄像头”和“第一台可用”的行为；沿用已确定的约10秒快照、点开才实时播放的规则。离线、无兼容设备、切换家庭和权限撤销要有明确状态。

验收：指定来源／第一台来源都能显示同一设备的快照并点开；切页不重复建立视频流；旧家庭快照不得残留。需要连接真实 HomeKit 摄像头验证，模拟器不能替代。

### R5 — 中优先级：编辑和更多设备的入口不容易发现

**界面观察与代码确认的产品缺口。** 已有增删／改大小，但没有手动移动排序。分类控件的更多设备主要依靠长按后的“上一个／下一个”，普通上下滑动已关闭；用户难以知道同一位置还有别的设备。长按菜单又同时混合导航、切换内容、尺寸、添加、恢复默认和删除，层次过重。“恢复默认”立即覆盖布局，没有撤销。

冻结版本 `Dashboard.swift:606–643,664–684,892`。大尺寸摄像头及混合尺寸截图还显示，自动装箱留下的空位很难由用户自行调整。

建议：增加一个清楚、轻量的编辑入口，编辑时统一完成添加、移动、尺寸和删除；分类卡提供可发现的设备选择，不把所有功能塞入长按菜单。恢复默认提供撤销或明确确认。保持普通浏览页简洁，具体入口位置在下一轮设计中对齐。

验收：用户不用记隐藏手势即可添加第二盏灯、把常用卡片移到首屏、调整大小并恢复误操作；全屏翻页与内容滚动互不抢手势。

证据：`probe-shots/review-native-home-long-press-menu-on-chinese-simulator.png`、`review-shots/landscape-widget-overflow-and-right-shortcuts.png`。

### R6 — 中优先级：参数已调好，但仍像有未提交的修改

**在 DEMO 状态复现。** 将温控调至24°C并应用，确认读到24°C后，“当前24°C／设为24°C／应用到设备”仍同时显示，应用按钮仍可点击。对用户而言，不清楚操作是否已经结束。

原因：`AccessoryAdjustmentView.swift:40–52` 的 `requestedValue` 在成功后没有清除，也没有与当前确认值比较。外部设备更新后滑杆可能继续显示旧草稿，这是代码推断，未作真机验证。

建议：确认成功后结束草稿状态；只有新值与已确认值不同时允许提交。处理进行中、失败和外部更新时分别保留清楚的反馈。再按设备类型优化温度、亮度和颜色详情，避免所有能力都变成长表单。

验收：成功后不再重复提交同值；失败保留用户选择并能重试；真实设备回读而非按钮点击决定成功。

证据：`probe-shots/review-adjustment-applied-but-same-draft-remains-actionable.png`。

### R7 — 中优先级：设备全部离线时，整个控制布局被替换

**代码确认，未做真实断网试验。** `HomeStore.refresh` 在全部附件不可达时设置 `.offline`，而 Home 页只有 `.ready` 才显示仪表盘；因此原有卡片、音乐／时钟等内容一同被状态页替换。

冻结版本 `HomeModel.swift:276`、`Dashboard.swift:374–384`。

建议：已有家庭只是设备离线时保留布局，以单卡离线状态和重试反馈表达；音乐、时钟等独立能力继续可用。权限撤销／切换家庭的隐私清理应继续执行，不能将这两种情形当普通离线保留旧数据。

验收：附件全离线和部分离线均保留正确布局，禁止不可达设备写入；恢复后回读；撤权仍清除家庭内容。

## 已有可保留的部分

- 三列左网格、右侧等行高矩形及两个横屏方向通过现有几何／UI检查；不建议再次推翻结构。
- 图标切换电源、文字打开详情且不改电源的现有旅程通过；温控箭头、元数据范围和只读状态相关测试通过。
- 基本添加／删除／改大小及持久化旅程通过，问题集中在发现、排序和操作后的反馈。
- Home 音乐卡与音乐页共用播放状态，拖进度／按钮操作不误触页面切换的合成数据旅程通过。
- 中文与大字号基础布局旅程通过。大字号采用现有滚动适配，不能因此推定所有弹层和真机布局均已验收。
