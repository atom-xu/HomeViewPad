# HomePad 开发经验

本文记录 HomePad 的开发约定与经过验证的实现经验。以原生 SwiftUI、公共 Apple API、本地数据和明确权限为边界；历史源码归属见 [CREDITS](../CREDITS.md)。

### 壁纸缩略图的裁切与无障碍范围（2026-10-23）

适用条件：固定比例的预览内部使用 GeometryReader、带偏移的背景图形和 clipShape。原生截图中的预览实际为 320×200pt，但 XCTest 的 AX 框一度为约 437.7×335.2pt，包含裁切外的图形范围。给预览明确 contentShape(Rectangle()) 后，同一原生像素与尺寸／比例检查通过，没有放宽断言或把图片拉伸来适应 AX。证据为 `.validation/local/dynamic-screensaver-10/mac-layout.xcresult` 与 `mac-layout-final.xcresult`；只适用于本次已复现的装饰预览，不据此替代实际截图检查。

### 不同壁纸来源共享最后一次选择意图（2026-10-23）

从尚未完成的照片导入改选航拍时，只取消航拍下载还不够：旧照片完成后会把来源切回静态。保留旧照片副本，单独取消旧照片导入并失效其 generation；只有当次导入明确成功才退出航拍模式。受控迟到响应验证航拍选择保留、旧照片内容与磁盘副本未变；相关 11 项航拍单元与照片导入 UI 已通过。证据在同版本 `mac-gallery.xcresult`；此结论针对应用内异步意图，不代表任何硬件控制验收。

## 每次迭代

1. 读取 `AGENTS.md`、`SETUP.md`、当前交接记录和涉及模块；检查 Git 分支与未提交工作。
2. 用几句话写清用户场景、预期结果、本次范围和验收方式。遇到产品规则未定时保留待确认项，不让测试替用户决定规则。
3. 在独立功能分支上修改，尽量沿用现有组件和服务入口。存在并行工作或需要试验性修复时，用独立 worktree 保护原现场。
4. 先复现，再区分环境、应用和测试失败。对行为改动运行 HomePad 的 XCTest/XCUITest；布局改动查看导出截图。
5. 按版本记录通过、失败、未测项，指出遗留问题和下一步。交接、提交、推送、发布和真机验收分别留证。

## 现有架构边界

- `Dashboard.swift`、`OverviewBoard.swift` 和 `WidgetCarousel.swift` 负责页面与交互；设备写入统一由 `HomeModel.swift` 中的 `HomeStore` 处理。
- `PhotoLibraryStore.swift`、`WeatherStore.swift`、`WeatherLocation.swift` 和 `Services.swift` 保持各自权限、取消和资源生命周期。
- 演示数据保持确定且可见标记，真实数据不可用时展示失败状态；不得自动拿演示值填补真实设备或网络故障。
- 扩展设备协议或引入新服务前，先定义权限、错误恢复与设备回读方式。保持系统原生能力的已有边界。

## 问题记录格式

每条新经验只写问题场景、可复现原因、已验证处理、证据位置和适用边界。未经验证的猜测放在当前交接的待办，不进入长期规则。

### 原生音乐容器的无障碍标识（2026-10-16）

音乐页从 ScrollView 改成 GeometryReader／VStack 后，父视图的 accessibilityIdentifier 被传播到播放按钮、标题和专辑曲目，覆盖其独立标识。失败结果包的实际 AX 树显示多个不同控件均叫 musicPage 或 musicCoverFlow。为这些非叶容器明确设置 accessibilityElement(children: .contain)，保留原有按钮／歌曲断言后，Home 联动选歌与中文最大字号两项专项均通过。证据在 `.validation/local/music-implementation-01/` 的 focused／repair 失败包及 ax-check 成功包；仅适用于已观察到标识传播的自定义 SwiftUI 容器，不据此覆盖叶子控件的语义。

### 共享媒体服务的被动打开与刷新（2026-10-17）

音乐页和 Home 复用同一 MusicStore 时，页面 task 每次调用 open 再强制 refresh，会让已连接的内容短暂变成 connecting，清空正在浏览的专辑并重复资料库请求。新增回归在原实现上复现 ready／选中专辑／请求次数断言失败；open 先检查实时权限、再复用 ready 或连接中的前台状态后，该用例通过。显式 Refresh 和后台后重返仍重新加载；权限变为 denied 时立即清空数据，未确定授权的连接中状态不取消用户正在完成的系统弹窗。证据为 `.validation/local/music-interaction-02/reopen-repro.xcresult` 与最终回归中的同名单元测试。此经验适用于同一个前台服务被多个入口复用，不能据此跨后台保留私人资料或跳过权限检查。

### 页面动画期间的 UI 测试就绪检查（2026-10-17）

适用条件：从 Home 打开音乐页后立刻操作子页入口。本轮两项新增 UI 用例在 Dashboard 0.46 秒进入动画中的约 0.33～0.34 秒点击 Library，失败时 AX 仍停在播放器；这不证明具体坐标命中的原因。仅在测试侧先确认播放器存在、Library 可点击且 frame 连续稳定，点击后要求 Cover Flow 出现，原导航／失败反馈断言全部保留。应用源码不变，121 单元与四项音乐 UI 最终 125／125 通过，有效结果包和截图保留。XCTest 空闲与元素存在不能单独替代后续可操作状态；不要用删断言或改生产交互来掩盖测试同步问题。见 [最终复测](evidence/ipad-music-interaction-full-suite-summary.json)。

### 原生快照事件必须绑定当次请求（2026-10-17）

只读审查确认：nonisolated HomeKit delegate 把事件投到 MainActor 后才读取可替换的 completion，旧事件排队期间若取消再请求，就可能取得新闭包。每次请求使用独立 delegate／delivery，事件只持有当次对象；取消清旧对象的闭包，交付前先清闭包再调用。受控回归验证旧事件排队→取消→新请求不消费新 completion，以及回调内再次取消／排队只交付一次；135 项单元通过。此证据针对 app 内回调绑定，不声称相机硬件已复现。HomeKit 没有公开取消已发快照的接口，不能把摘 delegate 写成取消摄像机拍摄。

### 长按预览要检查实际系统托管结果（2026-10-17）

本机 iPadOS 26.5 中，UIKit 把自定义 SwiftUI contextMenu preview 托管为 label 为 Preview 的容器，移除应用指定的 preview identifier；设备按钮在其中变为包含名称／房间／状态的组合标签。保留整体与数字／文字边界断言，按实际托管节点验收。截图又复现系统白底使白色原控件不可读；给独立预览明确前景和不透明可读底、限制最长边并留边后，温控及边缘灯光预览 1／1 通过，截图确认完整。仅改变菜单预览，不据此修改正常卡片布局或系统主题。原失败 AX、视频和修复包见本轮 VALIDATION。

### 音乐局部拖动与页面翻页的归属（2026-10-17）

适用条件：沉浸式 Dashboard 的 simultaneous 横向翻页与子页 Cover Flow 共存。本轮新增用例先复现整页排除导致播放器不能切页；仅按全局 frame 排除后，完整回归又复现快速反向翻专辑误进照片。失败视频与 XCTest 触摸记录确认起点在专辑区域内，不能仅因动画中 frame 变化就归咎测试。改为音乐页自己的低优先级分页，Cover Flow 使用局部高优先级；播放器封面另外取消拖动末尾的点击，保证轻点仍进入专辑。根分页在音乐／待机下用 GestureMask.subviews 从识别阶段退出；独立的活动手势只记交互，不导航。结束回调读取已被子回调改变的 page 不能作为唯一防重复条件，这项是只读审查的风险判断，并非声称已经观察到双翻页。

最终应用的六项音乐 UI 已通过，覆盖封面左右切页／返回、进度条不切页、快速反向翻专辑、专辑外空白切页、五个子页退出与恢复、中文最大字号入口和原有播放状态断言。证据在 `.validation/local/music-page-navigation-04/`；精确快照与完整／专项结果见 VALIDATION。不把模拟器的合成 TEST DATA 当作真实发声或实体手势验收；也不据此认为所有 SwiftUI 滑动冲突都适用同一种修复。

### 绝对偏移网格的新增控件定位（2026-10-23）

在使用 ZStack／offset 装箱的 Home 网格中，新增卡片只追加配置后位于视口外；直接按卡片 ID 调用 ScrollViewReader.scrollTo 的首次修复仍未定位成功。为每一行加入实际参与垂直布局、不可交互且对无障碍隐藏的行锚点，再定位到新增卡片的末行；新卡完整进入视口且短暂高亮。新增UI保留“无需手动滚动，完整卡片在视口内”的断言，通过并检查原图。适用于该偏移画布，不据此替换普通 List／LazyVGrid 的原生定位。见 `.validation/local/home-controls-11/` 的 focused 失败与 isolated-home-final 成功结果。

### 编辑行语义和 iPad 原生确认弹出框（2026-10-23）

同一环境（Xcode27.0、iPadOS26.5）中，编辑行的父 identifier 覆盖了行内尺寸 Menu 的 identifier；失败 AX 树只出现 layoutRow 的按钮。为行明确 children.contain 后，尺寸／移到最前入口恢复独立可访问语义，实际排序与取消恢复的UI旅程通过。原生 confirmationDialog 又把同一确认 identifier 暴露在父子两个按钮节点，iPad弹出框没有独立取消按钮；测试依据实际节点选择确认，取消时点击框外，并继续断言自定义布局没有丢失。不能因为查找失败而删除排序／取消后的状态断言，也不能把一个系统标签假设成所有语言和平台的恒定结构。既有长按 Preview 查询同时接受中文“预览”，温控、边缘灯卡和最大中文字号的完整边界断言保留且通过。

### App 语言不能代替系统选图器语言（2026-10-23）

独立 iPadOS26.5 模拟器有8张测试图片，App显式使用英文，但系统 PhotosPicker 的原生 AX 图像标签为“照片, …”，完成按钮为中文。只查“Photo,”的旧测试错误报告缺少种子照片。独立诊断记录实际 AX 与原图后，仅让测试接受英语／中文照片标签和原生 Add／Done／添加／完成节点，同时排除 App 自己的 dismissPanel；原两张选择、保存数量、取消、重启、全屏几何、音乐背景恢复和壁纸替换／删除断言全部保留，三项完整旅程3／3通过，应用源码字节不变。不要通过重播种造成重复照片，也不要为了通过测试改用户系统语言或弱化数据结果断言。证据：`.validation/local/home-controls-11/photo-probe.xcresult`、`photo-localization.xcresult`。

## 本轮产品范围经验

用户给出参考图并明确“复刻，只增加一列”时，保留原图的构图、主次、文字位置和交互呈现；不能自行改为带家庭标题、房间筛选与快捷列表的控制台。先用独立验收模拟器的实际运行截图对照参考，再更新用户正在看的预览模拟器；不让自动测试接管用户预览。按已明确的范围继续执行，不把每次内部样式选择都变成用户确认。系统 Liquid Glass 使用原生公开接口，不把背景绘制或自制玻璃当作需求本身。

## 原生透明控件的触控与测试

2026-10-16 在 iPadOS 26.5 模拟器复现：采用原生 Liquid Glass、plain Button 与透明背景后，控件的无障碍边框可能覆盖整张卡，但文字／图标之间的空白区域未必响应点击。导航中央点击会穿透到下面的卡片；同样影响快捷卡长按菜单。已为完整卡片和导航标签明确设置 `contentShape`，四宫格导航与快捷方式创建、打开、重启恢复及删除的两项复测均通过。证据为 `docs/evidence/ipad-reference-navigation-summary.json`；其余完整回归另见 VALIDATION，不以这两项替代。

Form 中 menu Picker 的无障碍框也可能包含整行，但菜单入口在右侧当前值。测试应点可见的当前值并验证选项与持久化；全行都应响应的自定义按钮，需要明确铺满标签与触控区域。待机预览按钮曾因空白位置不响应而失败，补齐 44pt 高度与整行触控区域后，预览、触摸恢复及夜间偏好保存的复测通过。

同轮进一步复现：Form 中 automatic 样式的诊断按钮即使已有整行 label 和 `contentShape`，行中央点击仍可能不触发。失败 AX 与录屏确认按钮启用、事件坐标准确且 Settings 未离开，不能改成查任意标题来绕过。为诊断与断开连接按钮明确 `.buttonStyle(.plain)`，保留可见强调色、破坏性角色及原断言后，四种错误状态、返回真实引导与重新进入演示全部通过，连同 29 项单元测试共 30 项零失败。证据为 `docs/evidence/ipad-reference-diagnostic-summary.json`。此经验适用于自定义整行 Form 按钮，不据此更换系统 Picker 的交互方式。

## 全屏页面与正方形组件

2026-10-16，最初把“控件保持正方形”误解成横竖屏都固定四列，导致竖屏卡片变小、下方大量空白。用户澄清：竖屏可以在底下多增加几行，图标可以更大，控件尺寸应一致。当前规则是横屏在右侧增加一列，竖屏保留原三列并把快捷功能移到底部；按列宽算正方形边长，不按全部内容高度压小，每个新增组件继续向下排。主板按内容高度展开、禁用内层独立滚动，由一个外层列表连同底部快捷统一滚动。大温控仍为 2×2。精确检查横竖屏边长一致、跨格比例、间距、底部位置和滚动可达性，再看实际中英文截图。单侧顶部 padding 曾多出 6pt；对称 padding 后保留原 12pt 顶边断言。

正方形网格在较宽横屏上居中留白后，`homePage` 的无障碍容器框只包住子内容，不能用它证明背景是否铺满视口。本次单项复测实际读到：11 寸横屏 app／现有 `navigationBackdrop` 均为 1210×834pt，`homePage` AX 为 `(63,12,1084,822)`。测试改测本来就承担空白处导航的全屏背景，同时保留页面存在及所有精确网格断言；不放宽方形尺寸、不为测试增加无需求的产品边框。首次完整 59 项保留 58 通过、1 失败的原始结论，单项修正复测通过，最终完整结果另见 [VALIDATION.md](VALIDATION.md)。适用于 SwiftUI 透明容器和留白布局，不能据此省略真实像素检查。

验证组件布局持久化时，只让该布局使用真实保存值，其他不相关设置采用明确的测试 fixture。本次新加“滚到竖屏底部设备控制”检查时，测试机保存的快捷配置实际没有该按钮，六次滚动都无法找到它；不能据此改应用的滚动实现。仅为此用例固定默认快捷配置、保留真实组件布局后，改尺寸、重启恢复、旋转、滚到底部与恢复默认均通过，单项 72.878 秒。见 [VALIDATION.md](VALIDATION.md) 的原始路径。

## 本轮源码变更登记

### 音乐撤权回调的清理顺序（2026-10-16）

真实使用迭代的同步 fake adapter 复现：音乐权限撤销后，清理先调用 pause，再移除播放观察者，pause 同步通知观察者又进入权限清理，最终递归导致栈保护 SIGSEGV。模拟器 crash 栈重复包含 `MusicStore.applyAuthorization → clearTransient → pause → TestMusicClient.pause → playback callback`。改为先失效请求代际、移除观察者，再暂停，原撤权用例及全部 112 项单元测试通过（冻结快照与完整 UI 结果另见 VALIDATION）。适用于清理动作本身会触发回调的适配器；此复现来自可控同步客户端，不声称原生 MusicKit 已发生过同一崩溃。原日志与脱敏栈在 `.validation/local/real-use-01/music-revocation-crash-audit.json`。

### 旧场景捷径不能继承其他家庭（2026-10-16）
