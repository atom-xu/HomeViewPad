# HomePad architecture and privacy

HomePad is an independently developed SwiftUI iPad dashboard, iPadOS17+, with no third-party packages or app-owned server. Source attribution is recorded in [Credits](../CREDITS.md). The checked-in Xcode project contains app, XCTest unit tests, and XCUITest UI tests. Its generator uses only Python's standard library.

- `Dashboard.swift`: presentation, sheet navigation, foreground state, display preferences, and adaptive widget board. The current app declares only the two landscape interface orientations; the existing portrait layout code remains dormant. Native controls provide keyboard/VoiceOver semantics. Scrolling and flexible card grids handle changing size classes. Text uses semantic styles except the intentionally scalable hero clock. Power state remains in VoiceOver values; visible icon and card appearance indicate power without a repeated On/Off caption. Offline and unavailable states stay visible. There is no essential animation. Optional foreground face-presence detection is described below.
- `HomeModel.swift` and `HomeTileFactory.swift`: main-actor HomeStore with deterministic demo and lazy real HMHomeManager, household/generation guards, and characteristic discovery from the public catalogs. Real writes validate permissions, availability and device metadata; readable controls remain busy through read-back. Public request-only commands report sent while waiting for actual state. Primary cards group by HomeKit service UUID and prioritize physical sensor/lock/door state or thermostat temperature; support diagnostics join only the same accessory. Cameras and their auxiliary information stay in the right column. Revocation/home switching clears private state.
- `AccessoryAdjustmentView.swift`: focused material controls with a vertical brightness control, metadata-snapped writes on drag completion, pending/read-back feedback and retry. Unavailable values disable writes; the HomeStore command boundary is retained.
- `WallpaperStore.swift`: a separate single-image PhotosPicker import for the full-viewport background. It does not request full-library access, change system wallpaper, enumerate albums or modify the photo page. ImageIO applies orientation metadata and bounds decoding to a 3072-pixel maximum edge off the main actor; only a JPEG copy is persisted. Atomic replacement and request generations preserve the previous background on cancellation/failure and reject late loads after removal or replacement. Settings offers selection and restore-default actions in English and Chinese.
- `AerialStore.swift`, `AerialCatalog.swift`, `BackgroundSettingsView.swift`: a unified Colors / Photo / Apple Aerial gallery shares the saved background with Home, Clock and clock standby. Twelve Apple-hosted aerials have verified video and preview URLs; only metadata is checked in. Explicit selection downloads a 1080p SDR HEVC movie over Wi-Fi, validates a playable video track and finite duration, generates a bounded still, then commits the selection. Cancel, background, another selection and failures preserve the prior source and reject late completions. A single muted AVQueuePlayer/AVPlayerLooper and aspect-fill AVPlayerLayer run only on a visible foreground background. Hidden pages, overlays and Reduce Motion release the decoder; Reduce Motion retains the still. No audio-session or AirPlay route is changed. Shuffle rotates downloaded clips without immediate repeats, with a deterministic catalog-order cycle in demo. Optional Debug-only fixtures require both `--uitesting` and `--aerial-fixture`, use an isolated cache/preferences domain and show TEST DATA; they never substitute for Apple-source playback evidence.
- `SettingsHubView.swift`: one full-page native NavigationStack and opaque grouped background, with a persistent Pages exit. Home, Display & standby, Content & permissions and General remain the main categories; Calendar, Weather city/units and Permissions have direct index entries. The same Dashboard stores and existing sheets serve these links. Permission rows read system status passively and refresh on foreground return; connection intent and permission are separate. No service, Home manager or authorization prompt is created merely to inspect the page. Help, About, wake options and diagnostics stay secondary.
- `PhotoLibraryStore.swift`: opt-in PhotoKit albums/Favorites and 1–24-image PhotosPicker import, generation-guarded requests and bounded 2048-pixel decoded images. Selected JPEG copies are saved atomically in the app sandbox; a four-image maximum wall and single-image presentation share the selection and 30-second rotation. A wall can also be selected for standby. Full access permits album enumeration; limited access displays only authorized images. A change observer refetches after edits/deletions, and foreground transitions recheck authorization. The photo panel never writes to the Photos library.
- `WidgetCarousel.swift`: reusable square slot with directional vertical transitions, bounded position dots visible during a vertical drag and for one second after switching and named accessibility actions.
- `OverviewBoard.swift`: opaque black two-by-two square composition with date, numbered clock, shared PhotoKit album and weather. Available as a separate page; Home is the initial page. Demo uses a fixed weather fixture; live mode observes WeatherStore.
- `WeatherStore.swift`: Open-Meteo forecast/geocoding client, city and units persistence, in-memory weather, 15-minute foreground refresh, cancellation/generation guards and explicit offline/stale states.
- `WeatherLocation.swift`: only an explicit Locate once action outside demo creates CLLocationManager or requests When In Use permission. A single city-scale fix releases its manager before Apple reverse geocoding; success saves the rounded city, while denial/failure preserves the selected city. No automatic following or background location mode.
- `PhotoWall.swift`: full-screen album composition, large digital clock and shared image crossfades. A `PhotoFrame` identity changes only when decoding completes.
- `Services.swift`: AVPlayer and AirPlay bridge, and a camera session with a 20-second connection timeout and explicit teardown. Camera presentation uses `HMCameraView`; no stream is saved. Lifecycle transitions pause audio and stop camera streaming.

## HomeKit device forms and controls 12

`HomeServiceCatalog.swift` maps all46 public services and33 accessory categories in SDK27 to system symbols, with current-state variants and guarded iOS18 additions. `HomeCharacteristicCatalog.swift` defines129 user-facing numeric, bool, enum, event and information characteristics; nine binary management/stream payload types are explicitly excluded. Actual valid values narrow public enum choices; numeric sliders require device bounds/step, and unknown primitives remain read-only. No category/symbol grants permission to write.

The same focused material detail view presents ranges, explicit lock/door/security modes, Active toggles, sensor readings, attached battery/filter diagnostics, and public media requests. Camera controls remain reachable from the existing camera flow. Notification-only buttons use their last event without an invented power state. The Debug coverage fixture requires demo plus explicit UI-test flags; production installation has neither. Complete definitions do not claim private Apple Home icon variants, system automation management, camera recordings/intercom, or independent HomePod queues. See [coverage](HOMEKIT-COVERAGE.md) and [iteration](HOMEKIT-CONTROLS-12.md).

## Home favorite controls 11

HomeWidgetKind retains camera/calendar decoding for migration, but left-column configuration filters both kinds. HomeFavoriteMigration moves them into HomeShortcut records with stable migration IDs and camera household scope, saving the destination before removing the old entries. Cameras and calendars occupy right-column rectangles only; reminders are not implemented. New and resized left cards scroll through real row anchors, avoiding offset-canvas ID geometry. A visible edit entry offers native row reordering, sizes, deletion and confirmed reset. Known authorized all-offline homes retain the dashboard; revocation and unknown initial failures keep their existing clearing/connection boundaries.

AccessoryAdjustmentView is a focused dark material control surface. Brightness uses a vertical adjustable control; other advertised values retain bounded controls. Drag completion submits a metadata-snapped value through HomeStore and matching read-back clears the draft. Failure retains a retryable selection. GlassSurface provides a dark contrast backing for clear native glass, including near-white photo backgrounds. System AirPlay remains user-selected; a matching Music settings entry does not implement a separate HomePod queue. See [scope](HOME-CONTROLS-11.md) and [coverage](HOMEKIT-COVERAGE.md).

## Music browsing 06, refined in 08

MusicStore retains an in-memory successful MusicPlaybackSource separately from the album/playlist currently browsed. Playback commits that source only after the existing generation/authorization success guards. A complete song-ID multiset, including duplicates, checks the source against actual queue readback; an already-assigned failed replacement cannot masquerade as the prior successful source. Skips and one-shot queue shuffle keep the source while its songs still match. Background, demo, disconnect and revocation clear it with other private state.

MusicPage keeps playback actions on the browsing screen. The persistent mini player explicitly opens the large player; its arrow and cover always return to the selectable Albums root, never to tracks or the queue. A confirmed playing album focuses its card; other sources may focus an album only through an exact current-song ID and unique library album-title/artist match. Missing or unknown sources still show the Albums root, including an honest empty-albums state with a Songs option. Only the lower-right transport button opens the queue. Queue Back opens the player, whose Back then exits to Albums. Unrelated browsing never rewrites the successful playback origin, and reopening an empty queue does not fabricate or persist a queue.

The library has selected Albums, Songs and Playlists segments. Albums and library songs share the same Cover Flow geometry, edge alpha mask and local drag ownership; browsing does not play, while selecting a song assigns the complete library at that index. Playlist browsing retains a list and occurrence-index track selection. Cover neighbours fade to zero. The final surface multiplies horizontal and vertical alpha masks, reserving vertical shadow space; the 0.23/0.77 vertical stops overlap the cover edges so top and bottom fade into the same backdrop. Large text uses semantic lists and Reduce Motion retains non-3D transitions. Search UI and every entry point were removed in 08; the bounded internal catalog-search service remains unused by this page. Compact shuffle/skip controls remain in the mini player. The header has matching 44-point AirPlay, Volume and settings glass targets. Volume presents the public MPVolumeView slider in a labeled native popover without reading or changing system volume itself; the simulator cannot validate that hardware slider. Redundant footer tutorials/actions are removed. Music options uses a native opaque Form and explicit primary/secondary system foregrounds rather than glass cards over the music backdrop.

## Playback and display 05

MusicStore loads all library song, album and playlist pages and every available track relationship batch. Album and playlist actions assign the entire playable song array; selecting an individual row uses its occurrence index so duplicate playlist songs remain distinct. Native ApplicationMusicPlayer queues explicitly reset inherited repeat-one and native shuffle. Collection shuffle orders the whole array once; reshuffling the actual queue includes already-played entries and starts its first shuffled entry again. Queue-entry identity, position and playing status come from native readback. The internal catalog-search API remains bounded; 08 removed its UI entry and does not introduce a merged multi-album queue. Demo/test data remain isolated and labeled.

MusicArtworkBackdropPolicy limits temporary playback artwork to Home and Clock. Home's music card shares the same store and optional blurred cover backdrop. Paused/unavailable playback, missing cover art or a selected local file restores the saved background without deleting it; Photos and Overview are excluded. A background-setting toggle controls this decoration, independently of the photo-wall source.

The existing explicit display.screenBehaviorV1 modes now distinguish system Auto-Lock, idle dimming of the current page, and idle clock/photos. The latter two use the configured idle timer even without motion sensing or while music plays. Current-page dimming records its presentation at entry and overlays a full-page wake-only control while hiding underlying accessibility controls; first touch restores brightness without activating a device or player. Original brightness/idle-timer state is restored on background. A manual preview remains clock/photos, not a current-page-dimming preview. Installations without a recognized explicit V1 selection retain their previous motion/upright policy until the user chooses; no preference or face-detection consent is migrated automatically.

Settings combines the Home/Clock/clock-standby background photo, colors and Apple aerials in one gallery with a shared preview. The independent photo wall retains its own source. Choosing a default color explicitly removes only HomePad's background photo copy and exits aerial mode; selecting aerials keeps the previous photo available. A connected Calendar view has an optional Add calendar to Home action using the existing shortcut persistence; no automatic calendar tile or new read permission is added.

## Data lifecycle

HomeKit owns the home database and permissions. HomePad does not export its home model. Home selection is available in Settings; its stable identifier is remembered. The first available home is used when the saved home no longer exists. Connection mode, display-awake preference and personal-display preference are in app-scoped UserDefaults, declared in the privacy manifest. No accounts, tracking SDKs, telemetry endpoints, analytics or external credentials exist. The optional live weather feature uses HTTPS requests to Open-Meteo.

The selected background wallpaper is stored separately as `Documents/background-wallpaper.jpg`. It fills the viewport using aspect-fill, so edges may be cropped without changing widget geometry. Canceling the picker preserves it; restoring the default deletes the copy and returns to the existing background preference. The local copy survives restarts and may be included in ordinary device backup. It has no app-owned upload or sync and does not follow system wallpaper changes. The independent Photos page and opaque Overview retain their sources; clock standby uses a translucent dimming layer over the shared background.

Apple preview images and explicitly selected movies are requested over HTTPS from `sylvan.apple.com`; the server receives ordinary connection/request metadata. No home, photo, calendar, location or music data is sent to Apple by this feature. Complete videos and stills live in the app's `Application Support/AppleAerials`, excluded from backup, with a 1,500 MiB total video limit and 750 MiB per download. The user can remove a download from its context menu. Shuffle only uses downloaded media and never automatically downloads a collection. A removed/missing selected video returns to the saved static source. Video selection, last shuffle item and interval persist in app UserDefaults; reading old static settings does not migrate them. There is no app-owned upload or synchronization. Apple's media is not bundled or relicensed by this open-source code.

Selected photos are downsampled and saved as JPEG copies under an app-owned selected-photo directory; a manifest makes multi-photo replacement atomic. A previous `Documents/ambient-photo.jpg` remains readable for migration. Remove displayed photos clears only HomePad's copies and selection. Files may be included in ordinary device backup; there is no app-owned sync service. PhotosPicker grants only selected items without requiring full-library permission. Album mode instead stores the selected collection identifier and rotation preference, fetches only authorized image assets and does not create a local album copy. Full access can enumerate albums and Favorites; limited access cannot reveal album names. A missing/restricted selected album is not silently replaced by All Photos. Source changes, inactivity and permission loss cancel PhotoKit requests; generation guards reject late results. iCloud images may download as needed. The app never changes or deletes library assets. Visible Overview/Photos and selected photo-wall standby advance every 30 seconds; sheets and background activity pause rotation.

AgendaStore reads the next seven days of calendar events only after system consent and the shared-screen opt-in; the explicit connection action records that intent and requests access in one flow. Read-only results remain in memory. Reminders are not requested or read. Disabling personal display or leaving the foreground clears them. A generation token prevents an earlier refresh from restoring cleared results. A foreground privacy cover helps obscure content during inactivity; physical observation of an unlocked shared screen remains possible. Any system permission can be revoked in iPad Settings.

Audio uses a security-scoped URL only for the current selected file; selecting another file releases the old scope. No permanent bookmarks or credentials are created. AirPlay selection is entirely system-mediated. The route picker delegate reports its presentation to Dashboard, so only that system picker may retain the current music surface through a transient inactive phase. Ordinary inactivity keeps the prior privacy cleanup; a true background transition always clears private music state and pauses playback, even with the picker open. Returning active rechecks authorization without reconnecting an already ready library. Dashboard owns this lifecycle rather than duplicating it in MusicPage. The app has no background audio mode.

## Maintainability boundaries

No SwiftUI view issues accessory writes directly. HomeStore provides a small command surface. Demo fixtures never instantiate HMHomeManager. Hardware-specific errors are displayed instead of replaced with sample values. Simulator tests validate app flows and fixture state, not HomeKit hardware correctness. Scene effects, remote reachability, signing entitlement and camera/AirPlay compatibility require the separate hardware checklist.

The app does not implement automation creation, multiple concurrent camera streams, camera intercom/recording history, arbitrary binary management configuration, or independent HomePod queues. Public mode/lock/blind controls are implemented by the catalogs above; actual hardware remains separate from simulated behavior.


## Upstream immersive navigation baseline

The original square Home composition and vertical widget gestures below describe the upstream baseline. The homepad revision supersedes those layout details as described in the next section.

`DashboardPage` defines Overview, Home, Clock, Photos and Settings; Home is the initial page. The immersive board fills `min(width,height) - 16` points and uses an explicit square frame for every slot, including the clock. The application requests hidden status bar and persistent system overlays using public SwiftUI APIs; the system can still reveal its own chrome. A tap recognizer on the uncovered wallpaper toggles navigation without intercepting widget buttons. Navigation overlays the bottom in portrait and the right side in landscape without resizing the board. The full-screen photo wall also accepts a background tap. Music remains a navigation shortcut. Overview has four fixed widgets (no widget carousel); it fills the entire viewport background with black and preserves square cells in both orientations. Its album opens the existing photo chooser. The clock draws white ticks, numerals and hands with a yellow seconds hand, without material or borders.

`DashboardSwipe` rejects short and ambiguous diagonal drags. Home pages use horizontal paging and vertical canvas scrolling; the legacy category stacks no longer consume vertical swipes. Session slot offsets select climate, clock, Add favorite, scenes, other devices and lights; category choices remain in the native menu, while new favorites pin explicit service/scene identities. There is no room filter in Home or the all-controls sheet. Household changes reset session offsets; switching a card never issues a hardware command. Existing scenes still require confirmation in their current presentation context.

The large-text layout retains square widgets in a single scrolling column. Vertical drags scroll this accessibility layout; named Next widget / Previous widget actions provide switching without competing with scrolling. Every slot also exposes Show navigation, and the page exposes next/previous page accessibility actions. The demo disclosure is integrated into the first widget. The Home wallpaper contains no personal data. The separate Photos page intentionally displays the chosen photo library content across the screen.

## Transition and photo loading lifecycle

Page transitions slide horizontally; widget transitions slide vertically, following the gesture direction. Navigation appears from the bottom or right according to orientation. Reduce Motion substitutes short fades. Each widget displays a maximum of five position dots; the active indicator and accessibility value identify its selection even in large homes.

The photo loader keeps the current authorized image while requesting the next one. It publishes the new frame, position and asset ID together only after a successful decode. The Overview album widget and wall crossfade between frame identities. ## Weather and location

New installations start without a weather city and with temperature units following the system region. Manual city search is the primary path. Only an explicit Locate once tap may request When In Use permission and one approximately three-kilometer-accuracy fix; Apple reverse geocoding supplies the city label. Its coordinates are rounded to two decimal places (about one kilometer) and the resulting city is persisted as an ordinary selection for future forecasts. Startup, foreground activation, panel opening, weather refresh and old follow-location flags never start or retry location. The lazy manager is released before reverse geocoding; the entire explicit request has a twenty-second timeout. Cancellation, true background, panel closure, failure and manual selection invalidate old requests. A temporary inactive permission alert preserves that explicit request. Denial/failure retains the selected city without inventing a fallback.

Versioned weather preferences preserve explicit legacy city/unit/follow values without rewriting old keys; the historical follow flag no longer authorizes location work. Existing installation evidence in app-owned persistent preferences also preserves the old implicit Philadelphia/Fahrenheit defaults. A completely empty sandbox cannot distinguish a never-used installation from an old installation that recorded no preferences; it is treated as new and unconfigured. Explicitly clearing a city persists as an empty selection across restarts. Successful one-shot selection stores its rounded city and clears the historical follow flag. Unknown preference versions and raw values are not silently overwritten merely by loading them.

City searches go to `geocoding-api.open-meteo.com/v1/search`; weather goes to `api.open-meteo.com/v1/forecast`. HTTPS uses an ephemeral URLSession with a 20-second timeout. Current model conditions, day/night WMO code and the selected city's daily temperature range are requested in Celsius with UNIX timestamps and its automatic timezone; display-unit conversion is local. The view credits Open-Meteo and the panel links to Open-Meteo and GeoNames. The current free endpoint is non-commercial; see [provider terms](https://open-meteo.com/en/terms) before a commercial distribution.

Weather readings remain in memory; the selected city (manual or one-shot rounded result), historical follow preference and units use UserDefaults. The provider may log requested coordinates/searches; the privacy manifest declares unlinked coarse location and search history for app functionality. No GPS point is sent to HomeKit or to an app-owned server. API errors retain a previous reading with an offline label; readings older than an hour are marked outdated. Forecast failures retry after two minutes, successful forecasts after fifteen, using only the saved city. A city/mode change clears old readings and invalidates in-flight callbacks. Demo never requests weather or location and does not substitute fixture readings for live failures.


## homepad iPad display revision (2026-10-16)

Home, Clock and Settings fill the viewport. As of the later wallpaper iteration, the shipping configuration supports landscape left and landscape right only, with `UIRequiresFullScreen` for the older iPad multitasking compatibility mode. These settings live in the generator as well as Info.plist. This does not modify the device rotation-lock setting. Newer windowed/resized modes remain controlled by iPadOS; landscape-only full-screen behavior must be validated separately on untested OS versions.

The retained layout implementation keeps the reference composition: a 2×2 climate tile, clock and an Add favorite slot beside it, and three equal device/scene tiles below. Landscape adds a fixed right column of customizable rectangular cards, with the same row height as the three square columns and width filling the remaining viewport. Portrait retains three columns and places the shortcuts in rows below the control board. Standard cells and icons retain the same size on rotation on the tested iPads, and the 2×2 climate tile stays square. Portrait calculates the side from its three-column width without a row-count/height cap. The main board expands to its packed content height with inner scrolling disabled; one outer `homePortraitScroll` scrolls controls and the bottom shortcut grid together. Extra controls or shortcuts add rows rather than shrinking all cards. Landscape retains its two independent scroll regions; 12-point outer insets and gaps remain. Large accessibility text uses a scrolling column. `HomeWidgetLayout.swift` packs small/medium/large widgets without overlap. Cards use native `glassEffect` on supported systems, with a material fallback for older iPadOS. A long press exposes navigation, add, size and removal actions; Add widget selects an actual accessory, scene or clock; cameras and calendars are configured in the right column. Layouts persist separately for demo and each HomeKit home. Unknown or unreachable readings never become a false Off state. Writes still use HomeStore's existing write/read-back contract. Vertical drags scroll overflow; long-press menus and accessibility actions change category contents. The normal Home surface has no household heading, room selector or section title; one compact Edit Home button opens layout editing. Home no longer displays photos; Overview and the independent Photos page retain them.

`L10n.swift`, the native string catalog and localized InfoPlist strings support system language, English and Simplified Chinese. User-created home, room, accessory and album names retain their source text. Current UI branding is HomePad; the project is homepad. Existing bundle identity and GitHub upstream paths are retained for installation/data continuity.

`DisplayCoordinator.swift` owns foreground idle timing, brightness restoration and optional hardware sensing. Without a recognized explicit mode, the preserved legacy policy requires continuous near-vertical stationary posture, fresh motion samples and no interaction before entering clock/photos. Explicit keep-current-page and idle-clock modes use inactivity without a posture requirement; interruptions restart their full idle window. Touch, enabled movement or optional face presence return to the previous page. Modal interactions suspend standby. Night settings use local time and support schedules crossing midnight. A background transition stops sensors and restores the captured brightness and idle-timer state.

Display & standby offers Follow iPad Auto-Lock, Keep current page, or Switch to clock or photos. The versioned explicit selection has precedence; reading older automatic-standby/keep-awake flags leaves every old combination unchanged, including unavailable motion hardware. Only a deliberate new selection writes the new key. Both app-managed modes expose an idle delay and explain first-touch waking; manual clock/photo preview is labeled separately. Wake sensing and detailed permission disclosures have their own destination. Screen behavior selection does not change face consent or night preferences. The scheduled night mode keeps its original stored value and schedule.

Face wake is off by default and requires an explicit setting plus system camera permission. Existing `display.faceWake=true` preferences retain standby-only capture. Non-standby foreground capture additionally requires the user's separate, versioned choice (`display.faceForegroundConsentVersion == 1`); missing, zero or unknown versions are not consent. Initialization, restored preferences and system authorization never grant this new scope. Turning continuous detection off clears its presence hold and restores standby-only capture. Turning face wake off also clears the additional consent, so re-enabling wake does not silently restore continuous sampling.

With both choices enabled and camera permission granted, low-resolution front-camera frames are checked locally with Vision at low frequency while the app is foregrounded without navigation or a presented interaction, including after waking. Presence updates an independent activity timestamp, preventing repeated dim/wake cycles while someone remains in view. After the last face observation, the complete configured idle delay and stable-orientation requirements must pass before automatic standby. Missing observations age out rather than blocking standby permanently; foreground resets discard previous observations. Generation guards reject callbacks from stopped sessions. Navigation, sheets, alerts and scene confirmations suspend detection; backgrounding stops it. The system camera indicator remains visible during detection. There is no identity recognition, recording, persisted frame, encoding or transmission. Device motion and proximity use only publicly exposed hardware capabilities; unsupported devices report unavailable. Actual capture continuity, sensing range, power and thermal behavior require physical-device validation.

The app is intended to stay open as a dedicated panel. Guided Access can be enabled by the user in system settings; supervised Single App Mode is a separate managed-device deployment. HomePad cannot unlock or wake a system-locked iPad. Research and source references are in [IPAD-KIOSK-RESEARCH.md](IPAD-KIOSK-RESEARCH.md); actual checks and untested hardware remain in [VALIDATION.md](VALIDATION.md).

## Real-use revision 01

`HomeDashboardGeometry` gives the left board three square columns, with unlimited packed rows. The fixed right column takes the remaining width, and each rectangular card has exactly the left cell's row height. Primary icons toggle supported power through HomeStore; names open `AccessoryAdjustmentView`, including service-scoped numeric brightness, hue, saturation and reciprocal-kelvin color-temperature display when readable metadata permits adjustment. Opening details never sends a command.

`MusicStore` lazily uses MusicKit's ApplicationMusicPlayer, with separate authorization, subscription, library/catalog requests, playback intent and request generations. Only an explicit Connect requests music access. Background, demo, disconnect and revocation clear transient private data and invalidate playback; switching to a file pauses pending music starts. The app stores only connection intent, not music account credentials or signing keys. MusicKit is enabled as an App Service for the explicit App ID, not a fabricated entitlement. Real service availability, account eligibility, playback and AirPlay require physical validation. `AgendaStore` similarly creates EventKit lazily, reuses existing consent on passive refresh, observes event changes, and discards late results after hiding/background. iPadOS exposes calendar reading as Full Access; the app never creates or edits an event.

`MusicPage` separates the immersive player, Cover Flow library, collection tracks and the actual player queue; 08 removes search UI. Library browsing loads all native song, album and playlist pages and all available playable-song relationship batches without assigning a queue. Only explicit collection, shuffle, song or queue selection changes playback. Album-list failures preserve successful song access. Now-playing entries, duration and position come from ApplicationMusicPlayer; the foreground observation reads its actual clock every 0.5 seconds and is removed on cleanup. Seeking clamps to a known duration, queue limits disable unavailable skips, and skipping a paused queue stays paused. Unknown timing is visibly unavailable. No artificial playhead or placeholder track enters real mode.

`MusicHomeWidget` observes Dashboard's same MusicStore and AudioStore in the existing right-column one-row rectangle; it does not create a second player or request access. Cover/title opens the full player, transport stays on Home, and an imported local file keeps its source ownership when paused until an explicit music action clears it. Drags originating inside the connected Home music card are excluded from Dashboard paging. MusicPage owns its lower-priority one-finger paging gesture; the Cover Flow drag and the player-artwork drag that cancels tap-to-library take priority. Reported global frames protect the seek timeline, header/transport controls, song/queue rows and mini player, with a twelve-point touch margin. The player artwork and remaining surface switch Dashboard pages. Dashboard disables its own paging recognizer with GestureMask.subviews while Music or standby owns the sequence, so a child page change cannot enable a second root onEnded; a separate non-navigating drag records activity. A standby drag wakes without paging away from the previous page. A labeled Pages button in the shared Music header opens Dashboard navigation from every music subpage and connection state; it is independent of the music-internal Library/Back button. Page switching retains the session music path and playback. Large accessibility sizes use a list in place of Cover Flow and scrollable semantic text. AirPlay and volume remain public system controls.

`MusicNavigationState` is session-only Dashboard state, separate from the MusicPage view identity. It keeps a browsing path and stable album/playlist/song IDs across page switches, while the Home card and mini player explicitly open now playing. Background, permission loss, disconnect and demo changes reset it with the music privacy boundary. A recreated collection-tracks surface reloads only its selected browsing request. Passive `MusicStore.open()` rechecks permission and reuses ready/in-flight foreground data; explicit refresh or returning from background still reloads. Song/queue selection waits for the completed operation and matching actual current entry, then remains on its browsing surface; failure also leaves the source visible. The player's back arrow always opens the selectable Albums root, focusing a confirmed or unambiguously resolved playing album independently of the last browsed item; it never implicitly opens queue/details. Cover Flow owns its drag and edge return; Reduce Motion removes its 3D rotation and animated moves. Artwork/backdrop transitions are keyed to actual track identity, not an invented playback clock.

`MusicValidationClient` is compiled only under Debug and selected only when both `--uitesting` and `--music-fixture` are explicitly supplied. Its synthetic metadata and queue do not create a MusicKit player, request permission or play sound. The separate simulator uses deterministic Home demo hardware with conspicuous TEST DATA music labels. Ordinary launches and Release builds cannot select this fixture; the physical install uses no test/demo flags. It is UI acceptance evidence, not account or audio validation.

`CameraConnectionView` shows connection/explicit-selection states from the chosen HomeKit home. `SidebarCameraCard` uses a Dashboard-owned `CameraSnapshotStore` and HomeKit's public snapshot control, rendering each actual `HMCameraSnapshot` with `HMCameraView`. Only a user-selected, reachable camera with a visible foreground card registers for polling. Requests are separated by at least ten seconds, with one in flight per camera even when multiple cards share it, and a twenty-second timeout. HomeKit can return an earlier capture; its actual capture date is retained and labeled earlier instead of claiming a new image. Failure preserves a prior snapshot with a visible update-failed status. The default unconfigured card does not select a camera implicitly.

Hiding a card, opening a sheet/navigation, or standby removes its consumer and stops polling while retaining its in-memory authorized frame for return. Inactivity/background, demo and unavailable Home access clear frames and invalidate requests; switching household also discards registrations and profile references, and card identity includes its household. No snapshot is exported or persisted. HomeKit exposes no cancellation for an already issued snapshot; cancellation detaches this app's delegate/completion, while store generation, entry and request identities reject late delivery. Each native request has an immutable delivery/delegate pair, so an event queued before cancellation cannot consume a replacement request's completion when it later enters MainActor.

An explicit camera open still starts a muted foreground live stream and closing/background stops it. Repeated start of the same already starting/live owned stream is idempotent. Cleanup checks delegate ownership before stopping a stream. Home access to remote cameras is distinct from local front-camera face sensing consent. No RTSP credentials, recordings, microphone capture or backend are added. Physical camera timing, network behavior and live viewing remain separate hardware acceptance.

iPhone photos require the same Apple Account and iCloud Photos to sync into this iPad's visible library. Public PhotoKit Favorites is supported; inspection of Apple's public collection types and the current SDK found no dynamic Featured Photos or Memories source. The app therefore offers selected photos/albums rather than claiming access to system curation.
