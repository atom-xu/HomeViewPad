# 固定面板的天气城市 07

## 用户场景

用户将 iPad 固定放置，不需要随设备移动持续跟随城市。手动选择城市是主路径；需要时由用户点击“定位一次”获取城市，此后保存该城市并停止位置请求。天气数据仍可按已选城市正常刷新，天气刷新不等于重新定位。

## 范围与验收

- 启动、回前台、普通天气刷新、旧 followsLocation 偏好均不得自动创建位置管理器或请求定位／权限。
- 只有显式“定位一次”可申请 When In Use 并获取一次位置；成功后保存为所选城市并释放位置／逆地理资源。
- 失败、取消、关闭页面、后台要停止，保留已有城市；迟到结果不能覆盖后来手动城市。单位、旧手动城市和未知偏好值保护保持。
- 清楚说明定位只运行一次；网络／Apple 逆地理失败要有手动选择的退路，不把模拟数据当真定位。
- 可控客户端验证成功／资源清理／拒绝／取消／迟到；UI 检查手动城市与明确的一次权限入口，并查看截图。真实 Apple 逆地理服务仍独立记录。

## 结果与限制

已合入手动城市与显式“定位一次”。定位按钮成功后保存取整城市、停止位置与逆地理请求；普通天气刷新只读取已存城市。取消、拒绝、超时、后台和后来的手动选择均使旧请求失效。权限页说明与按钮名称一致。

音乐06完整回归期间先在忽略目录 proposal 验证，结束后核对基线和候选散列才应用七个文件。独立候选的169单元全部通过；手动城市 UI 通过。首次权限 UI 只匹配英文，而系统弹窗实际为中文；第二次被上次失败遗留的同一系统弹窗挡住。仅修正实际观察到的中英文选择器与重置前的定向清理后，真实权限拒绝 UI 1／1 通过。原失败包保留；这些是测试准备问题，不称应用定位缺陷修复。

实际工作区合并后，169单元、原生显式请求／拒绝／不重试 UI、手动搜索／保存／重开／实况天气 UI 也分别通过。主路径没有依赖真实定位成功；Apple 逆地理服务真实成功仍未验收，成功保存、超时与资源清理由可控客户端覆盖。[完整记录](VALIDATION.md)与[精确结果](evidence/ipad-music-browser-weather-summary.json)。
