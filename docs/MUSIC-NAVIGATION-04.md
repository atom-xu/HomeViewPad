# Music page navigation 04

## 用户场景与范围

真实连接音乐后，单指左右滑动不能离开音乐页。现有全页排除用于保护 Cover Flow 和进度条，却同时屏蔽了播放器与空白处的全局翻页。

本轮只调整导航与手势归属：播放器／空白处恢复单指横向切换 HomePad 页面；Cover Flow 封面区保留翻专辑，进度条保留拖动播放位置，搜索输入区保留文字选择。实际音乐按钮／曲目列表区域保持本地操作，页头常驻有文字的「页面」入口，可从播放器、专辑、曲目、队列、搜索与未连接状态选择其他页面。继续保留音乐内部返回、浏览位置、Home 音乐卡手势保护及 AirPlay 生命周期。不改 Home 布局、权限或音频路由策略。

## 验收方式

先用确定且标记 TEST DATA 的独立模拟器用例复现已连接播放器单指不能切页，再验证左右离开和返回；拖进度不切页、Cover Flow 只切专辑。逐一验证各音乐子页的页面入口、返回恢复及中文最大字号可达性。运行 HomePad scheme XCTest/XCUITest，导出检查截图并记录环境与失败。真机更新到已授权 iPad 后，普通启动与用户实测分别记录；不以模拟器代替硬件结果。不提交、推送或公开发布。

## 状态

- 原实现新增回归 0／1，复现播放器左滑不能进入设置。首次修复专项 2／3；封面拖动结束仍触发点击，返回后落在专辑浏览。给封面增加取消点击的拖动识别后，左右往返专项 1／1 通过，截图已检查。
- 第一份完整 scheme 有效结果包为 **170／172**（135 单元全部通过、35／37 UI）。失败是既有自动城市解析超时和快速反向翻专辑误切到照片页。原始视频与实际触摸坐标确认起点在 Cover Flow 内，不能归因于测试时机或删断言。
- 音乐页改为自行处理低优先级分页，Cover Flow 及播放器封面优先处理拖动；135 单元＋六项音乐 UI **141／141 通过**。随后只读审查发现根 simultaneous 回调按结束时 page 判断，仍有重复翻页的顺序风险；最终候选从识别阶段禁用音乐／待机下的根分页，另以无导航副作用的手势记录活动。
- 最终应用 48 文件快照 `0b9b7c2bdb5b716723f27a69588dc81216db6ed0150d251c81c880cb8d5c5fbf` 执行期间未变，135 单元和 12 项相关 UI 的有效结果为 **146／147**；六项音乐 UI 全过。唯一失败是新增连续预览探针：第二次打开未出现待机，尚未执行拖动。保留 AX／视频／事件，不声称该路径已修复。
- 后续只改 UI 测试：完整恢复原点击唤醒／夜间用例，新增独立启动的滑动唤醒用例。其余 47 文件及签名应用不变，测试快照 `215cb47cb52875c28d33cc075bee73a3767d111b123c6a5823171e452298a488`。首次只实际执行原用例 **1／1**，新用例未被收录，不能按请求数量算通过。仅移除独立模拟器的测试 runner 并改用新 derived data 后，新滑动用例实际执行 **1／1 通过**：滑动唤醒后仍是原设置页。三个结果包覆盖最终应用的 135 单元和 13 个不同 UI 方法通过；不是单一完整全绿套件。
